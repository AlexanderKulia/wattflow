# Dedup key is (device_id, reading_id), never bare reading_id

Ingestion dedups on the tuple `(device_id, reading_id)`, not `reading_id` alone. Nothing guarantees reading_id is globally unique — a producer using per-device sequence counters would emit the same reading_id for different devices. Deduping on the bare ID would treat two different devices' readings as duplicates of each other and silently drop one, corrupting both devices' aggregates. The tuple form is correct under either global-unique or per-device-unique ID schemes and costs nothing extra. The content-hash fallback already includes device_id, so this keeps both dedup paths consistent.
