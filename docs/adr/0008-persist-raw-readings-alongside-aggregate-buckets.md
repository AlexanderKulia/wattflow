# Persist deduped raw Readings alongside app-computed aggregate Buckets

Storage writes both the app-computed Bucket (ADR-0007, replace-on-conflict upsert) and the deduped raw Reading it was built from, to a separate Timescale hypertable partitioned on timestamp. TimescaleDB's own `time_bucket()`/continuous aggregates could compute the Bucket instead of the app doing it — but the aggregation module, and the bitwise-identical-regardless-of-delivery-order invariant it guarantees, is this project's core correctness demonstration. Delegating bucketing to the database would remove the reason that module exists. The app-computed Bucket stays the source of truth for the correctness invariant; the raw Reading table is an audit trail, not a computation shortcut.

Raw Reading inserts are `ON CONFLICT (device_id, reading_id) DO NOTHING`, not replace — a Reading is an immutable fact once ingested, unlike a Bucket, which is a running total that can legitimately be recomputed and replaced (ADR-0007). A TimescaleDB continuous aggregate over the raw table is an optional read-path addition (ticket 09) for comparison against the app-level aggregate — never a replacement input to the correctness harness.
